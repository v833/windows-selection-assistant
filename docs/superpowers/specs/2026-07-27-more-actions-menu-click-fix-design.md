# 原生动作菜单点击无响应修复设计

## 问题

划词工具栏通过 Windows 原生菜单展示“更多动作”和多选项动作。用户点击菜单项时，`selection-hook` 会先发出全局 `mouse-down`；当前 `SelectionService` 判断点击位置位于工具栏窗口外后立即隐藏工具栏。原生菜单以工具栏窗口为宿主，宿主被隐藏后菜单在 Electron 的 `click` 回调执行前关闭，因此动作没有被触发。

## 修复方案

在 `SelectionService` 中增加原生菜单交互状态：

- 菜单打开前设置为活动状态。
- 活动期间忽略用于隐藏工具栏的鼠标、滚轮和键盘事件。
- 菜单关闭回调中恢复普通自动隐藏行为。
- “更多动作”菜单和工具栏动作的多选项菜单统一通过同一个弹出函数处理。
- 动作真正执行时仍由现有 `showAction` 主动隐藏工具栏并显示结果窗口。

不采用无宿主菜单，因为 Windows 下定位、层级和焦点行为不够稳定；不改写为 HTML 菜单，因为范围过大且会丢失原生键盘导航。

## 错误与边界处理

- 如果菜单弹出失败，立即恢复自动隐藏状态并重新抛出错误。
- 菜单通过点击、Esc 或失焦关闭时，都由 `Menu.popup` 的关闭回调恢复状态。
- 状态方法使用布尔值，不引入计数或嵌套菜单管理；Electron 的子菜单属于同一次原生菜单生命周期。

## 测试

- 单元测试验证菜单活动期间，工具栏外部鼠标点击不会隐藏窗口。
- 单元测试验证状态恢复后，外部点击继续正常隐藏工具栏。
- 单元测试验证菜单活动期间滚轮和键盘不会提前隐藏工具栏。
- 运行全量测试和生产构建。
- Windows 冒烟验证“三点 → 二级动作”和工具栏多选项动作均能打开结果窗口。

## 发布

修复合并到 `main` 后发布补丁版本 `v0.4.1`，提供安装版、便携版和 SHA256 校验文件。
