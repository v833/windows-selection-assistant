# 按动作配置模型与提示词变量设计

## 背景与目标

当前应用只保存一组 OpenAI 兼容接口配置，所有动作共享 API 地址、密钥、模型和固定请求参数；自定义提示词也只能保存普通文本。Issue #5 要求在不破坏旧设置和默认体验的前提下，让用户按动作选择不同 Provider、模型、温度和最大输出，并提供可验证、可预览的提示词变量。

本次实现遵循以下原则：

- 默认仍使用全局配置，未主动展开高级配置的用户不需要额外操作。
- Provider 作为命名配置集中管理，动作只保存引用与覆盖值，避免重复密钥。
- 二级动作继承所属主动作的请求配置，暂不增加二级动作独立模型。
- API Key 只在设置存储中加密保存，不进入动作、预览、日志、结果窗口或历史导出。

## 方案选择

采用“命名 Provider 列表 + 动作可选覆盖”的方案。

未采用的方案：

1. 每个动作完整保存 API 地址、密钥和模型。实现直观，但会重复敏感信息，修改和轮换密钥也容易遗漏。
2. 只允许动作覆盖模型，不支持 Provider。改动最小，但无法满足不同兼容服务之间切换的需求。

命名 Provider 能保持配置集中，同时完整覆盖 Issue #5 的速度、质量和成本分流场景。

## 数据模型

新增 `ProviderProfile`：

- `id`：稳定标识，用于动作引用。
- `name`：用户可见名称。
- `baseUrl`：OpenAI 兼容 API 地址。
- `apiKey`：仅运行时存在的明文密钥。
- `defaultModel`：Provider 默认模型。
- `defaultTemperature?`：可选的 Provider 默认温度；留空时沿用旧版按动作类型选择的温度。
- `defaultMaxOutputTokens?`：可选的 Provider 默认最大输出 token 数；留空时不发送限制，交给模型服务决定。

`AppSettings` 新增：

- `providers: ProviderProfile[]`
- `defaultProviderId: string`

旧的 `baseUrl`、`apiKey`、`model` 字段从公开设置模型中移除，由默认 Provider 代替。

`SelectionAction` 新增可选 `requestProfile`：

- `providerId?: string`
- `model?: string`
- `temperature?: number`
- `maxOutputTokens?: number`

未填写的字段逐项继承所选 Provider 的默认值；未选择 Provider 时继承应用的默认 Provider。二级动作通过现有 `resolveActionVariant` 展开后保留主动作的 `requestProfile`。

新增内部解析结果 `ResolvedRequestProfile`，包含实际请求所需的 Provider、API 地址、API Key、模型、温度和最大输出。它只在主进程内使用，渲染进程只接收不含密钥的有效配置摘要。

## 设置迁移与密钥存储

读取旧版设置时，如果不存在 `providers`：

1. 使用旧 `baseUrl`、`model` 和解密后的 `encryptedApiKey` 创建一个名为“默认 Provider”的配置。
2. 使用稳定的默认 Provider ID，并设置为 `defaultProviderId`。
3. Provider 的温度和最大输出默认留空。解析时温度继续使用聊天 `0.4`、其他动作 `0.2` 的旧规则，最大输出继续不发送，从而确保升级后请求参数不变。

新格式持久化时，每个 Provider 的密钥分别使用 Electron `safeStorage` 加密。磁盘 JSON 保存 `encryptedApiKey`，不保存明文 `apiKey`。读取失败的密钥按空值处理，不把异常内容暴露到界面。

写入仍采用临时文件加原子重命名；只有磁盘写入成功后才更新内存状态。

## 有效配置解析与校验

主进程提供纯函数解析动作的有效请求配置：

1. 读取动作指定的 Provider，否则读取默认 Provider。
2. 校验 Provider 存在且 API 地址非空。
3. 模型优先使用动作覆盖，否则使用 Provider 默认模型；结果必须非空。
4. 温度优先使用动作覆盖，其次使用 Provider 默认值；两者均留空时使用聊天 `0.4`、其他动作 `0.2` 的兼容值。显式值允许范围为 `0` 至 `2`。
5. 最大输出优先使用动作覆盖，其次使用 Provider 默认值；两者均留空时不向服务发送该参数。显式值必须为正整数，允许范围为 `1` 至 `128000`。

设置保存时同时校验：

- Provider ID 唯一，名称、API 地址和默认模型非空。
- 默认 Provider 必须存在。
- 动作引用的 Provider 必须存在。
- 动作覆盖值和 Provider 默认值必须在允许范围内。
- 提示词不得包含未知变量。

校验失败时拒绝保存整个补丁，返回本地化、可定位到 Provider 或动作的错误消息，避免写入部分有效状态。

## 提示词变量

支持四个变量：

- `{text}`：当前选中的原始文本。
- `{language}`：设置中的目标语言。
- `{program}`：产生选区的来源应用名称。
- `{question}`：会话中最新一条用户问题；单次动作和尚无问题时为空字符串。

使用双花括号输出字面量：`{{text}}` 渲染为 `{text}`。渲染过程先保护转义片段，再替换支持变量，最后恢复字面量。形如 `{unknown}` 的未知变量会在保存时阻止提交，并显示“未知提示词变量：{unknown}”。普通 JSON、代码块和不构成单花括号变量的内容保持原样。

兼容规则：

- 提示词包含 `{text}` 时，不再自动追加“待处理文本”，避免重复原文。
- 提示词不包含 `{text}` 时，沿用当前行为，把提示词和选中文本一起发送。
- 内置动作无自定义提示词时保持现有系统提示词和用户消息结构。
- 会话请求中的 `{question}` 使用裁剪后会话里最新的用户消息，不从助手消息推断。
- JSON 提取 Schema 继续附加在最终用户消息后，不参与变量校验和替换。

## 请求数据流

1. 设置页编辑 Provider 或动作高级配置，渲染进程提交完整设置补丁。
2. 主进程清洗、校验并加密持久化设置。
3. 用户选择动作时，主进程解析有效请求配置，并把有效 Provider 名称、模型、温度和最大输出随 `ActionPayload` 发给结果窗口，不包含 API Key。
4. 发起请求时，主进程再次解析有效配置，以最新设置构造 URL、鉴权头和请求体。
5. 提示词渲染器根据选区、目标语言、来源应用和会话问题生成消息。
6. 结果窗口显示有效模型；会话历史继续保存实际使用的模型字符串。

再次解析而不是信任渲染进程传回的摘要，可以避免设置变化或渲染进程数据被篡改后使用错误密钥与模型。

## 设置界面

### Provider 管理

“模型”页面改为 Provider 列表：

- 默认只展开当前默认 Provider，显示名称、API 地址、API Key、默认模型、默认温度和默认最大输出。
- 支持新增、删除和设为默认；至少保留一个 Provider，默认 Provider 不允许直接删除。
- API Key 继续使用密码输入框和显隐按钮。
- “测试连接”针对当前编辑的 Provider 草稿执行，不依赖已保存状态。
- 列表和状态消息只展示 Provider 名称、模型及连接结果，不展示密钥。

### 动作高级配置

每个主动作增加折叠的“模型与提示词”高级区域：

- Provider 下拉项包含“继承默认 Provider”和已配置 Provider。
- 模型、温度、最大输出均可清空以恢复继承；Provider 的温度和最大输出留空时分别显示“兼容默认”和“服务默认”。
- 每项同时显示当前有效值及来源，例如“继承：默认 Provider / gpt-4.1-mini”。
- 内置动作和自定义动作都可编辑提示词；二级动作仍使用自己的现有处理提示词，但请求配置继承主动作。
- 提示词编辑器下方列出支持变量和转义示例，提供基于示例选区、当前语言、示例程序和示例问题的即时预览。
- 预览只包含渲染后的提示词和不敏感的有效配置摘要。

为控制复杂度，高级区域默认折叠，不新增独立页面，也不实现模型自动发现。

## 错误处理与安全

- Provider 或模型配置无效：保存时阻止提交；运行时若设置文件被外部破坏，则返回现有“配置错误”类别并引导打开模型设置。
- 提示词变量无效：编辑区就近显示错误，保存按钮不可用；主进程仍做最终校验。
- API Key 不得出现在提示词预览、IPC 有效配置摘要、错误消息、日志、会话历史或导出文件。
- 测试连接只向当前 Provider 的地址发送最小请求，错误分类沿用现有鉴权、模型、网络和服务端分类。
- Provider 删除前必须确认没有动作引用；如果存在引用，先要求动作恢复继承或切换 Provider。

## 测试设计

新增或扩展自动化测试：

1. 有效配置解析：默认继承、指定 Provider、逐项覆盖、重置继承、缺失引用和数值边界。
2. 提示词渲染：四个变量、双花括号转义、未知变量、`{text}` 去重、旧提示词兼容和会话最新问题。
3. 请求构造：实际 URL、鉴权、模型、温度和最大输出来自有效配置。
4. 设置迁移：旧全局配置迁移为默认 Provider，聊天与非聊天温度行为不变。
5. 设置持久化：多个 API Key 均加密，序列化结果不含明文密钥。
6. 设置校验：未知变量、无效 Provider 引用、重复 Provider ID 和越界参数拒绝保存。
7. 结果载荷：有效模型显示正确，载荷和导出不含 API Key。

手动验证：配置两个 Provider，让翻译继承快速模型、代码动作覆盖为强模型，分别执行并检查结果窗口模型标签；再测试旧式无变量提示词和包含 `{text}` 的新提示词均只发送一份原文。

## 完成标准

- 所有动作默认继承应用默认 Provider。
- Provider、模型、温度和最大输出可以按主动作覆盖并恢复继承。
- 四个提示词变量在单次动作和多轮会话中按约定渲染。
- 未知变量阻止保存并给出中文错误。
- 旧设置升级后请求地址、密钥、模型和温度行为不变。
- 结果窗口展示实际模型，任何非加密输出不包含 API Key。
- 类型检查、现有测试和新增测试全部通过。

## 范围外

- Provider 市场、模型列表自动拉取、自动测速和计费统计。
- 二级动作独立 Provider 或模型。
- 提示词条件表达式、循环或用户自定义变量。
- 云端同步 Provider 与动作配置。
